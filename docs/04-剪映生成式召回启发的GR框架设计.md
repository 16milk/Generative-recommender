# 剪映生成式召回启发的 GR 框架设计

> 本文结合两份内部材料《剪映/CapCut生成式召回》《剪映生成式召回推荐架构》，并对齐本项目已有的背景综述、Meta HSTU 代码框架梳理、OneRec 系列论文梳理，给出一套可从零实现的 **Generative Recommender（GR）生成式推荐框架**。配套的精细架构图见：[`generative-recommender-architecture.html`](generative-recommender-architecture.html)。

---

## 1. 目标与定位

本项目的目标不是简单复刻某一篇论文，而是沉淀一套 **工业可落地、可 scale、可持续迭代** 的生成式推荐框架：

- **从判别式到生成式**：把召回从 `<user, item, context> -> score` 改写为 `user behavior sequence -> next semantic id(s)`。
- **从级联到统一模型**：以一个生成模型承载召回能力，并逐步向排序 / 重排 / post-training 对齐扩展。
- **从样本工程到序列建模**：召回不再只依赖负采样与双塔空间，而是通过多级 SID 对齐全量 item 空间，用自回归建模学习用户兴趣迁移。
- **从短期实验到平台能力**：沉淀 tokenization、listwise 数据流、训练、serving、监控、AB 策略等模块化能力。

### 1.1 推荐的阶段性目标

| 阶段 | 目标 | 关键产物 | 成功标准 |
|---|---|---|---|
| P0：最小闭环 | 跑通生成式召回训练和离线评估 | pointwise/listwise 样本、SID、baseline 模型 | HR@K / MRR 可稳定复现，能反查候选 |
| P1：可服务化 | 在线生成 SID 并召回 GID | 推理服务、SID->GID 检索、merge 策略 | 延迟、空结果率、召回量可控 |
| P2：规模化 | 支持长序列、较大模型和更大 beam | listwise 数据流、GPU serving、cache | 离线 hitrate 呈 scale trend |
| P3：对齐优化 | 引入业务 reward / DPO / GRPO | RL trajectory、reward model、post-train | pass@1、效率、独占占比提升 |
| P4：统一推荐 | 召回、排序、重排逐步融合 | one-model 多任务生成框架 | 减少级联损失，统一优化业务目标 |

## 2. 从内部材料抽象出的核心经验

### 2.1 生成式召回为什么值得做

内部材料对动机的总结可以归纳为三点：

1. **长期愿景：End-to-End / one model serve all**  
   传统多级级联会累积误差；生成式框架将召回、排序甚至重排统一为序列生成和偏好对齐问题，技术路径更接近 LLM/LRM 的 scale 逻辑。

2. **中期主线：提升 scale-up 上限**  
   LRM 参数上到一定规模后 ROI 下降，本质可能是个性化参数和稀疏特征效率不够。生成式推荐把用户行为序列转化为 next-token 任务，样本利用率更高、MFU 更好，更有机会形成推荐领域的 scaling law。

3. **短期落地：解决召回的样本空间和 UG 交叉痛点**  
   多级 SID 能模拟全量样本空间；逐级生成 SID 的过程中，每一层都能与用户侧信息交叉，潜在建模了 `user x group/item` 的交叉信号，理论上限可向精排靠近。

### 2.2 工业落地的关键结论

| 模块 | 经验结论 | 对本项目的设计含义 |
|---|---|---|
| 数据流 | listwise 比 pointwise 更适合 scale，MFU 更高；pointwise 适合敏捷 baseline | 同时保留 pointwise baseline 与 listwise 主线 |
| 序列窗口 | session 聚合噪声低但短；滑动窗口更适合规模化，但要处理资源和重复训练 | 采用 `long seq + short/listwise seq` 双序列，配合 req_time mask |
| Tokenizer | SID 质量决定上限；均匀度、path 利用率、collision、在线有效率都重要 | 先做 RQ-Kmeans/RQ-VAE baseline，再引入 balanced / GAOQ / n-gram |
| 模型 | encoder-decoder 易理解；decoder 才更适合 scale；SID decoder 可单独设计 | 先实现 encoder-decoder baseline，再演进 decoder-heavy / decoder-only |
| Reward | SFT 足够做出召回；RL 更多提升 pass@1 和业务对齐 | P0/P1 不强依赖 RL，P2 后引入 reward post-train |
| Serving | SID 倒排准、ANN 稳；beam、merge、保送、采样都影响占比和效率 | Serving 策略必须配置化和可 AB |
| 效率 | beam 预截断、FlashAttention、KV cache、GPU serving 是关键 | 架构上预留 kernel / cache / dynamic config 能力 |

## 3. 框架总览

完整 GR 框架可以拆成六个层次：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 6. 观测与治理：数据校验 / 特征覆盖 / SID 有效率 / 延迟 / AB / 回滚       │
├────────────────────────────────────────────────────────────────────┤
│ 5. Serving：序列特征获取 -> 生成 SID -> SID/GID 检索 -> merge -> 下游   │
├────────────────────────────────────────────────────────────────────┤
│ 4. 训练：Pretrain NTP / Listwise SFT / Reward SFT / DPO-GRPO          │
├────────────────────────────────────────────────────────────────────┤
│ 3. 模型：User Encoder / Decoder / SID Decoder / Reward Heads          │
├────────────────────────────────────────────────────────────────────┤
│ 2. Tokenizer：Embedding Source -> Quantization -> SID 评估 -> 索引      │
├────────────────────────────────────────────────────────────────────┤
│ 1. 数据：Pointwise / Listwise / Long Seq / Short Seq / RL Trajectory   │
└────────────────────────────────────────────────────────────────────┘
```

其中 **数据层、Tokenizer 层、模型层、Serving 层** 是第一阶段必须打通的主链路。

## 4. 数据层设计

### 4.1 三类训练数据

| 数据类型 | 形式 | 作用 | 优先级 |
|---|---|---|---|
| Pointwise | `history -> next SID` | 最快复用传统样本，做 baseline | 高 |
| Listwise | `history + gid_1...gid_n -> sid_1...sid_n` | 高 MFU、scale 主线 | 最高 |
| RL Trajectory | `beam SIDs -> rank/VT/reward` | post-training 偏好对齐 | 中后期 |

### 4.2 推荐样本格式

一个 listwise 样本建议包含：

```text
user_profile: 静态用户画像，如年龄/性别/城市/设备等
long_seq:     长期正向行为序列，作为稳定兴趣压缩，可来自 sim service / 离线湖
short_seq:    近期高信息密度行为序列，包含更多 side info 和 label
target_seq:   待回归的 gid/sid/action/timestamp 序列
item_side:    gid 对应的作者、时长、类目、内容理解特征等稳定特征
context:      req_time、场景、入口、action bitset、session 信息
```

### 4.3 序列窗口策略

建议采用内部材料中的折中方案：

- **long seq**：长期核心行为序列，长度可从 300 起步，后续 scale 到 1k/4k/更长。
- **short/listwise seq**：以用户为粒度维护滑动窗口，优先 play/export/like 等强正向行为。
- **过期机制**：用户超过 `N day` 无新行为则清理窗口，控制资源；剪映经验中 3 天窗口能取得较好的长度与资源平衡。
- **重复训练 mask**：由于流式 listwise 样本之间可能重叠，需要记录用户最近训练到的 `req_time`，对重复 gid 做 mask。

### 4.4 批式与流式

| 链路 | 作用 | 风险 | 建议 |
|---|---|---|---|
| 批式回溯 | 快速获得历史训练集，便于 cold start 和重训 | 与流式窗口不完全一致 | P0 必做，先接受分布 diff |
| 流式 joiner | 构建最贴近线上分布的 listwise 样本 | cache、checkpoint、延迟、资源复杂 | P1/P2 建设 |
| 流式入湖 | 支持重训和长期样本保存 | 存储成本高 | 与训练闭环同步建设 |

## 5. Tokenizer / Semantic ID 设计

### 5.1 Embedding Source

SID 的上限首先取决于底层 embedding。推荐同时评估：

1. **多模态内容 embedding**：标题、文本、OCR/ASR、封面/帧、类目等。
2. **行为协同 embedding**：i2i / swing / co-watch / co-export / graph embedding。
3. **多任务 cotrain embedding**：将内容语义和协同行为共同建模，避免 G 侧纯多模态与 U 侧行为分布错位。

建议增加一个 **Emb-based 双塔基线**：固定 G 侧内容 embedding，只训练 U tower。如果双塔都远低于主召回，说明 embedding/SID 上限不足；如果双塔接近主召回，则优先优化量化和生成模型。

### 5.2 Quantization 路线

| 方法 | 优点 | 风险 | 适用阶段 |
|---|---|---|---|
| RQ-Kmeans | 简单、稳定、便于评估 | 分布可能不均，需 balanced 约束 | P0/P1 baseline |
| RQ-VAE | 可学习，表达更强 | codebook collapse / hourglass | P1+ |
| Balanced RQ-VAE | 分层均匀度更好 | 整体 path 仍可能稀疏 | P1+ |
| GAOQ / 正交量化 | 均匀度和利用率潜力好 | 解码方式和实现更复杂 | P2 |
| Prefix-ngram / Engram | 扩充词表容量，缓解 path 稀疏 | sparse emb / serving 复杂 | P2/P3 |
| End-to-End Tokenizer | 理论上最优 | 容易坍缩，训练不稳定 | 探索分支 |

### 5.3 SID 评估指标

SID 不应只看离线聚类指标，需要离线 + 在线双评估：

| 指标组 | 指标 | 含义 |
|---|---|---|
| 均匀度 | Gini、相对熵、code 利用率 | 码本是否被充分使用 |
| Path | path 覆盖率、平均挂载数、孤点簇、最大簇 | SID->GID 是否过稀或过热 |
| 语义 | i2i hitrate、embedding reconstruction hitrate | 是否保持 item 语义邻近 |
| 在线有效性 | SID->GID 命中率、空结果率、召回占比 | serving 是否可用 |
| 业务效率 | Export/Show、Like/Show、独占效率 | 是否真正带来价值 |

经验上，**均匀度差时在线通常不会好**；均匀度提升有利于召回占比提升。但推荐天然存在马太效应，均匀度与语义可分性之间需要权衡。

## 6. 模型层设计

### 6.1 Baseline 架构

建议 P0 采用容易实现和调试的 encoder-decoder：

```text
Encoder input:
  [user_profile tokens] + [long_seq item/action/context tokens] + [short_seq tokens]

Decoder input:
  [BOS] + [sid_level_1] + [sid_level_2] + ...

Decoder output:
  next SID level / next item SID path
```

训练目标：

```text
L = Σ CE(pred_sid_l, target_sid_l) * reward_weight(action, label)
```

### 6.2 可演进方向

| 方向 | 设计 | 价值 |
|---|---|---|
| Decoder-heavy | 缩小 encoder，把参数放在 decoder | 更符合 scale 经验 |
| Decoder-only / Lazy Decoder | 去 encoder 或弱化 cross-attention | 降低训练 / 推理成本 |
| HSTU backbone | 使用推荐原生 attention | 长序列效率更高 |
| SID Decoder | 主干输出 hidden，再由专门模块解多层 SID | 建模 SID 层级依赖 |
| Session Mask | 同请求内 item 互相可见 | 更符合推荐 item 无强顺序性 |
| Listwise Set Loss | 预测未来一组 item 而非严格顺序 | 降低顺序噪声 |
| MoE / Sparse FFN | 扩大参数而不线性增加 FLOPs | 支持大模型 |

### 6.3 Mask 与训练/推理一致性

内部材料强调：推荐 item 序列不像文本那样天然有严格顺序。应明确选择训练和 serving 对齐的策略：

- **Causal Mask**：适合连续生成 top-k item，能建模 list reward，但推理长、需要解决生成 SID 后如何取 side info。
- **Session Mask**：适合一次请求内多 item 无序生成，单点采样多 token，更符合召回阶段的覆盖需求。

P0/P1 推荐先用 causal baseline；P2 后探索 session mask / set loss。

## 7. 训练与对齐

### 7.1 Pre-training / SFT

核心目标是学习用户行为序列模式，而不是一开始就强行优化所有业务指标：

```text
Input:  user profile + long seq + short seq prefix
Target: next SID path / next SID list
Loss:   next-token CE + action/reward weighted CE
```

建议权重：

- show 权重低或仅作为上下文；
- play/clickshot/export/like/comment/share/download/finish 等作为 action bitset；
- 可先人工设置 reward weight，例如强化 export/like，再由 post-training 学习。

### 7.2 Post-training / Preference Alignment

当 SFT 模型有足够 hitrate 后，再引入：

1. **Reward SFT**：用真实 UA label 或精排/VT score 加权 CE。
2. **DPO / Listwise DPO**：构造 chosen/rejected SID 列表。
3. **GRPO / GBPO**：对 beam 结果做组内 advantage，优化 pass@1。
4. **Format / Valid Reward**：鼓励生成有效 SID，惩罚空结果。
5. **Diversity / De-dup Reward**：避免坍缩和重复，提升覆盖。

对召回阶段来说，RL 不是 P0 必选项；因为召回优化的是 hitrate@K，大样本 SFT 往往已经足够。但当框架开始直接影响排序出口或要提升 pass@1 时，post-training 会变重要。

## 8. Serving 层设计

### 8.1 在线主链路

```text
1. sort / recall 请求进入
2. 获取 user profile + long seq + short seq
3. 调用 GR model 生成 beam 个 SID path
4. 通过 SID 倒排或 ANN 找到 GID list
5. 多 SID merge / 去重 / 打散
6. 送粗排 / 精排 / 混排
7. dump serving trace 作为后续训练与 RL trajectory
```

### 8.2 SID->GID 检索方案

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| 倒排 / DSL Filter | 准确、可控、支持分层检索 | path 稀疏时空结果率高 | 主线 |
| ANN by SID embedding | 空结果率低、结果有序 | 稀释生成模型能力，依赖 emb 可反解 | baseline / fallback |
| Trie constrained decoding | 直接生成有效 path | 工程复杂 | P2+ |

### 8.3 Merge 与策略

| 策略 | 说明 | 经验 |
|---|---|---|
| Snake Merge | 多个 SID 轮询取结果，增强多样性 | 初期稳健，覆盖多兴趣 |
| Score Merge | 按 SID 概率顺序优先取头部 | 适合模型排序能力强时 |
| Beam Size | 增大 beam 提升覆盖，但降低平均效率和增加延迟 | 需 AB 调参 |
| Temperature / Gumbel TopK | 引入探索性 | 低温接近 beam search，建议保留开关 |
| Guarantee | 保送精排提升数据循环和占比 | 不宜过高，避免挤压其他高效队列 |

### 8.4 推理效率优化

优先级建议：

1. **GPU / 高性能 serving**：CPU 很难支撑大 beam 和大模型。
2. **Beam 预截断**：先局部 top-M 再全局排序，降低显存和计算，内部经验可带来明显延迟下降。
3. **FlashAttention / fused op / BF16**：减少 attention 和 FFN 开销。
4. **金字塔 Beam**：前层 SID 粗粒度、后层细粒度，按难度分配 beam。
5. **KV Cache**：用户短期重复请求时复用 encoder / long-seq KV。
6. **动态参数**：`beam_size / temperature / topk / guarantee` 通过请求 context 传入，支持 AB。

## 9. 监控与正确性

### 9.1 数据正确性

- 用户基础特征长度为 1 或 NULL。
- 序列特征在每行内长度一致。
- v1/v2 fid slot 规则校验通过。
- label bitset 与原始 label 下标一致。
- 批式和流式样本核心字段 schema 对齐。

### 9.2 在线监控

| 监控项 | 说明 |
|---|---|
| SID 有效率 | 生成 SID 是否存在对应 GID |
| 空结果率 | SID 检索无结果的比例 |
| 召回数量 | recall / merger / coarse rank / rank 各层数量 |
| 链路通过率 | merger、粗排、精排通过率 |
| 占比 / 独占比 | GR 对最终展现的贡献 |
| 效率指标 | Export/Show、Like/Show、时长、留存等 |
| 延迟 | user data、model inference、index retrieval、整体 p99/p999 |
| 数据循环 | GR 样本是否持续进入训练，是否存在分布漂移 |

## 11. 最小可执行路线图

### 11.1 第 1 周：离线样本与 SID baseline

- 准备公开数据集或内部脱敏样本。
- 构建用户行为序列：`uid, gid, action, ts`。
- 训练 / 导入 item embedding。
- 实现 RQ-Kmeans SID。
- 产出 `gid -> sid path` 与 `sid path -> gid list`。
- 评估 SID 均匀度、path 利用率、反查 hitrate。

### 11.2 第 2 周：Pointwise GR baseline

- 构造 `history -> next SID` 样本。
- 实现 encoder-decoder 小模型。
- 训练 next SID CE loss。
- 离线评估 HR@K / MRR / SID path 有效率。

### 11.3 第 3–4 周：Listwise 与 Serving 模拟

- 构造 listwise 样本和重复 mask。
- 实现 beam search。
- 实现 SID->GID 倒排检索与 merge。
- 用离线 replay 评估召回覆盖和延迟。

### 11.4 第 5 周以后：Scale 与对齐

- 增加 long seq 和更多 side info。
- 放大 decoder、加入 HSTU / MoE / decoder-only 分支。
- 引入 reward-weighted SFT。
- 建设 RL trajectory，尝试 DPO/GRPO。
- 优化 serving：GPU、FlashAttention、beam 预截断、KV cache。

## 12. 设计原则总结

1. **先闭环，再 scale**：先让 `数据 -> SID -> 模型 -> 检索 -> 评估` 可重复运行。
2. **先 SFT，再 RL**：没有稳定 hitrate 前，不急于复杂 post-training。
3. **SID 是第一瓶颈**：均匀度、有效率、语义保真、在线占比都要监控。
4. **训练/推理必须一致**：mask、beam、side info、候选池、SID 版本都要对齐。
5. **策略参数必须动态化**：beam、temperature、merge、guarantee 都需要 AB。
6. **工程可观测性优先**：生成式召回链路长，任何 SID、特征、cache 异常都会放大为空结果和效果波动。
7. **面向 one-model 设计，但分阶段落地**：召回先行，排序/重排/agentic 推荐作为后续扩展。
